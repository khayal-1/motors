# خطة التنفيذ المرحلية — El Khayal Motor's

## المرحلة 1 — الأساس (هذه الدفعة)

- **ما سنبنيه:** هيكل Next.js/TypeScript RTL، إعداد Supabase SSR عبر متغيرات البيئة، تدفق تسجيل/دخول/خروج/استعادة كلمة مرور، مخطط PostgreSQL أولي، RBAC قابل للتوسعة، وسياسات RLS وهيكل توثيق وتشغيل.
- **لماذا:** تثبيت أساس آمن وقابل للاختبار قبل وظائف المخزون والعملاء والبيع؛ تكلفة تصحيح الصلاحيات بعد إضافة البيانات أعلى.
- **الملفات:** `app/`, `components/`, `lib/supabase/`, `lib/auth/`, `middleware.ts`, `supabase/config.toml`, `supabase/migrations/20261118180000_foundation.sql`, `.env.example`, `.gitignore`, `README.md`.
- **تغييرات قاعدة البيانات:** جداول الملفات الشخصية والأدوار والصلاحيات والتعيينات، جدول الدراجات والوسائط وسجل التدقيق، فهارس أرقام الهيكل/الموتور، trigger لملف العميل ودور Customer، وسياسات RLS. ملف migration فقط؛ لا يطبّق تلقائيًا على مشروع Supabase الحي.
- **المخاطر:** إعداد قائمة redirect URLs والبريد في Supabase مطلوب لتشغيل auth؛ تعيين أول Owner يحتاج مراجعة هوية المستخدم ثم خطوة إدارية يدوية؛ RLS لا يغني عن مراجعة السياسات عند إضافة عمليات جديدة. لا بيانات حقيقية أو مفاتيح سرية في المستودع.
- **الاختبار:** `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`، وفحص Git للتأكد من غياب `.env.local`. اختبارات قاعدة البيانات الحية تُجرى بعد مراجعة migration في بيئة Supabase المستهدفة.
