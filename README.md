# El Khayal Motor's — الخيال موتورز

منصة عربية RTL لمعرض دراجات نارية، مبنية بـ Next.js App Router وTypeScript وTailwind CSS وSupabase. تضم أساسًا آمنًا، كتالوجًا عامًا، حسابات عملاء، طلبات شراء/استيراد، وواجهات إدارة منفصلة للموظفين والمالك.

لا توجد بيانات عملاء أو مخزون مصطنعة، ولا دفع أو حجز بيع إلكتروني، ولا تكامل Telegram في هذه المرحلة.

## التشغيل المحلي

المتطلبات: Node.js 20.9+ وpnpm 11.9.0.

```bash
pnpm install --frozen-lockfile
cp .env.example .env.local
# أدخل إعدادات مشروعك محليًا في .env.local
pnpm dev
```

لا ترفع `.env.local` إلى Git. افحصه قبل commit باستخدام `git status` و`git check-ignore .env.local`، ولا تضع أسرارًا في `.env.example` أو أي ملف متعقب.

## إعداد البيئة

- `NEXT_PUBLIC_SUPABASE_URL`: رابط مشروع Supabase.
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: المفتاح العام الذي يستخدمه المتصفح.
- `NEXT_PUBLIC_SITE_URL`: أصل الموقع المستخدم لروابط تأكيد البريد والاستعادة.
- `SUPABASE_SERVICE_ROLE_KEY`: متغير خادم فقط لدليل الهاتف الخاص وإدارة الدعوات والتهيئة الأولية؛ لا تضعه في متغير `NEXT_PUBLIC_` أو في المتصفح.
- `OWNER_BOOTSTRAP_PHONE`: رقم المالك بصيغة E.164، يضبطه المشغّل سرًا في بيئة الخادم ولا يُحفظ في المستودع.
- `OWNER_BOOTSTRAP_TOKEN`: رمز عشوائي مؤقت قوي، يضبطه المشغّل مباشرة في البيئة؛ لا يُكتب في الكود أو المستودع أو المحادثة، ويُحذف بعد التهيئة.

صفحة `/setup/owner` لا تعمل إلا عند تهيئة قيم الخادم المطلوبة وتطبيق ترحيل إدارة الفريق. المسار غير مفهرس، يتطلب رمزًا مؤقتًا ويغلق نفسه بعد إنشاء أول Owner. دالة قاعدة البيانات ترفض أي استدعاء ليس من `service_role` وتستخدم قفلًا يمنع سباق تهيئة حسابين. لا توجد كلمة مرور افتراضية أو بيانات اعتماد ثابتة في الكود؛ لا ننشئ حسابًا أو نسند دورًا عند بناء التطبيق.

## التسجيل وتسجيل الدخول

- التسجيل العام ينشئ Customer فقط؛ الخادم وقاعدة البيانات يرفضان التسجيل الناقص أو بلا قبول موثق، ويُحجز رقم المالك من نموذج العميل عند ضبطه في بيئة الخادم. لا يوجد اختيار Employee/Manager/Owner/Admin في الواجهة.
- التسجيل يطلب الاسم الأول والأوسط واسم العائلة والهاتف والبريد وكلمة المرور وتأكيدها، مع قبول صريح لشروط الاستخدام وسياسة الخصوصية. يتحقق إجراء الخادم من الحقول قبل Supabase Auth ويحفظ إصدار الموافقة.
- تأكيد البريد ومسار العودة الداخلي الآمن محفوظان. لا يسمح `next` بإعادة التوجيه إلى موقع خارجي.
- تسجيل الدخول يقبل البريد أو رقم الهاتف وكلمة المرور. للهاتف المصري تُطبّع الصيغ المحلية إلى E.164. الحسابات المعتمدة على البريد تستخدم جدول ربط هاتف خاصًا لا تقرؤه أدوار `anon` أو `authenticated`؛ ويحتاج ذلك متغير الخادم ومهاجرة الهوية. الحسابات المسجلة بهاتف Supabase يمكنها المصادقة مباشرة.
- استعادة كلمة المرور الحالية عبر البريد، ثم تعيين كلمة جديدة من `/auth/reset-password`.
- الشروط وسياسة الخصوصية المتاحة حاليًا نسختان أوليتان تحتاجان اعتماد المالك ومراجعة قانونية قبل الإطلاق العام.

## فصل العميل عن الإدارة

مساحة العميل في `/account` و`/requests` لا تقبل إلا حسابًا يحمل دور Customer فقط؛ تمنعها فحوص الخادم وسياسات RLS عن حسابات الموظفين والمالك، ولا تمنح التسجيل صلاحية دخول إلى `/admin`. صفحات `/admin/inventory` و`/admin/team` و`/admin/team/permissions` محمية بتحقق خادمي إضافةً إلى RLS.

إدارة الفريق محصورة بمالك المعرض:

- دعوة موظف بالبريد مع الاسم والهاتف والدور؛ لا يتيح التسجيل العام إنشاء حساب موظف.
- إسناد وإزالة الأدوار المسموح بها؛ لا يمكن واجهة الإدارة إسناد Owner أو Customer.
- إيقاف حساب موظف وإزالة أدواره.
- تعديل صلاحيات الأدوار غير المحمية ومراجعة آخر تغييرات الأدوار والصلاحيات.
- عرض حالة تفعيل الحساب وآخر دخول متاح. لا يحصل أي موظف أو مدير على صلاحية الإدارة لمجرد حمل دور اسمه Admin أو Manager؛ دوال الخادم وسياسات قاعدة البيانات تشترط Owner.

تغييرات الأدوار والصلاحيات تسجل في `audit_logs`. تهيئة أول Owner منفصلة، لمرة واحدة وخادمية، وتحتاج تشغيلًا مقصودًا بعد إعداد البيئة وترحيلها. لم يُنشأ أو يُعيّن حساب مالك حي بهذا التغيير.

## قاعدة البيانات وعمليات النشر

المخطط يستخدم PostgreSQL ومفاتيح أجنبية وفهارس وقيودًا وRLS. يشمل الأساس `profiles`, `roles`, `permissions`, `role_permissions`, `user_roles`, `motorcycles`, `motorcycle_media`, و`audit_logs`. العرض العام `public_motorcycle_catalog` محدود ولا يكشف تكلفة الشراء أو أرقام الشاسيه/الموتور.

- `20261118180000_foundation.sql` طُبّق يدويًا مرة واحدة على مشروع Supabase الصحيح بعد فحص خلوه. قاعدة المشروع تعرض المخطط وسياسات RLS؛ سجل ترحيل CLI ما زال غير متزامن. لا تعِد تشغيل SQL التأسيسي.
- `20261118190000_customer_requests.sql` و`20261118193000_staff_role_management.sql` و`20261119100000_clients_auth_separation.sql` ملفات في المستودع فقط ولم تُطبّق على Supabase الحي.
- قبل أي تطبيق، اربط CLI بالمشروع والهوية الصحيحة، وسوِّ سجل migration التأسيسي بأسلوب tracking-only، ثم راجع التغييرات المعلّقة. لا تستخدم `db push` قبل مقارنة الحالة الحية والسجل؛ هذا قد يعيد تنفيذ المخطط.
- لا تُجرِّب SQL Editor بديلًا عن سجل CLI؛ تطبيق SQL هناك لا يسجل migration history. لا تُعد تشغيل الأساس.

هوية الدخول والبريد يديرهما `auth.users`. جدول `clients` يحتفظ ببيانات العميل، ويربط `clients.user_id` مرة واحدة بـ`auth.users.id`; البريد لا يُنسخ إلى `clients`. الهاتف ومعلومات الاسم والعنوان والموافقة القانونية موجودة في `clients`, و`legal_data` يتيح حفظ بيانات قانونية إضافية. الجداول التشغيلية تحتفظ بقيم UUID الحالية في `customer_id` لكنها تشير إلى `clients.user_id`; سياسات RLS تتحقق من ملكية العميل أو صلاحية الموظف. تغييرات البريد تمر عبر Supabase Auth، وتغييرات الهاتف تحدث فهرس الدخول الخاص من خلال RPC مقيّد بالمستخدم. `profiles` يبقى سجلًا عامًا للأدوار والتدقيق وبيانات الفريق، لا مصدر ملف العميل.

`20261119100000_clients_auth_separation.sql` يضيف جدول العميل والفهرس الفريد، ينسخ بيانات ملفات العملاء الحالية دون حذف أو إعادة ترقيم، يغيّر علاقات الطلبات دون تغيير UUIDs، ويضيف سياسات/RPC وتحديث Auth trigger. ملف Auth الجديد ينشئ العميل باستخدام `auth.users.id` ثم يحفظ البيانات من جهة الخادم؛ لا يضع تفاصيل العميل في Auth metadata. بيانات البريد تظل لدى Supabase Auth. الترحيل يعتمد على ملفات الطلبات وإدارة الأدوار السابقة، لذلك لا يمكن تطبيقه منفردًا.

المعاينة الحية السابقة أظهرت 8 جداول الأساس، ولا جدول ترحيلات أو جدولي الطلبات وphone_login_index؛ حساب الهدف مؤكّد بالبريد لكنه بلا ملف `profiles` أو هاتف Auth، ودوره Customer. لم يتم التحقق من تعداد كل سجلات المشروع من تلك المعاينة، ولم تُكتب تغييرات حية. تعذّر تنفيذ CLI لأن الحساب لا يملك مسار رمز دخول آمن للـCLI؛ كلمة مرور قاعدة البيانات المحفوظة لا تساوي رمز Supabase CLI. يلزم استئناف التطبيق عبر CLI بعد إتاحة مسار مصادقة آمن، من دون استخدام `ahs-311`.
